# RAAST Bug Corpus

A structured, honestly-labeled collection of reproducible RTL defect specimens
for Persian, Arabic, Hebrew-facing pages and for Spanish (LTR) hosts that
embed RTL fragments. Every specimen ships as a minimal broken/fixed HTML pair
plus machine-verified evidence of what the RAAST engine detects.

The corpus serves two purposes:

1. Regression fixtures — each specimen exercises at least one rule id
   (`RTL001`–`RTL017`) and is re-checked on every engine change.
2. Teaching specimens — each pair shows one realistic defect and its accepted
   fix (logical properties, bidi isolation, Persian digits, ZWNJ joins,
   inverted marks, mirrored iconography).

## Layout

```
corpus/
  README.md            <- this file; the index below is generated
  samples/
    CS-001-css-direction/   broken.html  fixed.html  sample.json  evidence/
    ...
    CS-032-responsive/
```

## Specimen schema

Each sample directory contains exactly:

| File | Meaning |
|---|---|
| `broken.html` | Minimal self-contained page (10–40 lines) with ONE realistic RTL defect. Starts with an HTML comment `<!-- DEFECT: one-line description -->`. |
| `fixed.html` | The same page with the defect corrected. Starts with an HTML comment `<!-- FIX: what changed and why -->`. Must scan clean (zero P0/P1 findings under the sample's language profile). |
| `sample.json` | Machine-readable metadata (schema below). |
| `evidence/` | `before.png` and `after.png` headless-Chromium screenshots generated by `tools/corpus/evidence.py` at the declared viewport. Only present once screenshots have actually been produced. |

`sample.json` fields:

| Field | Type | Meaning |
|---|---|---|
| `id` | string | `CS-NNN` specimen identifier. |
| `title` | string | One-line human title of the defect. |
| `category` | string | One of: css-direction, bidi, typography, components, forms, tables, icons, responsive. |
| `language` | string | Language profile the specimen is scanned with (`fa`, `ar`, `he`, `es`). Matches the `lang` attribute of the page. |
| `direction` | string | `rtl` for fa/ar host pages, `ltr` for Spanish host pages. |
| `viewport` | string | Screenshot viewport as `WIDTHxHEIGHT` (e.g. `1280x800`, `375x667`). |
| `symptom` | string | What a human sees in a browser when the defect is live. |
| `rule_ids` | string[] | Rule ids the specimen is claimed to trigger. |
| `expected_findings` | int | Exact number of findings `raast doctor` reports on `broken.html` under `--language`. |
| `evidence` | object | Paths (`evidence/before.png`, `evidence/after.png`) of the before/after screenshots. |
| `status` | string | `lab-verified` — the specimen has passed `tools/corpus/verify.py`. |

## Honesty policy

- **Claims are machine-verified.** A specimen may list a rule id in
  `rule_ids` only if that rule actually fires when `broken.html` is scanned
  with the declared `--language`. `tools/corpus/verify.py` enforces this on
  every run; a specimen whose claimed rule does not fire must be repaired —
  never faked by weakening the claim or doctoring the scan.
- **Fixed means clean.** `fixed.html` must produce zero P0/P1 findings under
  the same language profile. A specimen whose "fix" still alarms the engine is
  not a fix.
- **Counts are exact.** `expected_findings` matches the real finding count on
  `broken.html` at the time of the last verification, including extra findings
  beyond the claimed ids.
- **Evidence only exists if it was produced.** The `evidence/` paths point to
  screenshots actually rendered by `tools/corpus/evidence.py` in headless
  Chromium at the declared viewport. Screenshots are never committed for
  specimens that were not rendered, and never hand-drawn to look like browser
  output.
- **Synthetic but realistic.** Every page is hand-written for this corpus; it
  is not copied from a production site and does not claim to represent any
  real project. The defects reproduce patterns that genuinely occur in the
  wild (physical margins, missing bidi isolation, broken ZWNJ compounds,
  letter-spacing on Arabic script, Western digits in Persian prose, missing
  RAE inverted marks, off-canvas drawers that ignore direction).
- **Limits are stated.** Static verification proves the engine fires the
  claimed rules; it does not prove rendering behavior on real devices. The
  screenshots show how the specimen renders in one headless Chromium at the
  declared viewport — nothing more.
